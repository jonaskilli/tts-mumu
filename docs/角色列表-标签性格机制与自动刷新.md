# 角色列表：标签/性格机制与自动刷新

> 说明角色管理（工具箱）角色列表的数据流、与配置列表/朗读规则/插件三者的联系，以及本次「自动刷新 + ⚠ 提示」的修改逻辑。
> 适用分支：`mumu_tts_github`

---

## 一、核心概念

| 概念 | 含义 | 存放位置 |
|---|---|---|
| 标签（tag） | 发音人的分类，如「女青年01」，一个标签对应一个配置项/发音人 | `system_tts_v2.config.speechRule.tag`（DB） |
| 性格（personality） | 角色的性格描述，如「晓晓」，用于区分同标签下的不同角色 | `config.speechRule.tagData["personality"]`（DB） |
| tagName（显示名） | 界面显示名 = 规则算出的名字 + 性格，例如「女青年01晓晓」 | `config.speechRule.tagName`（DB，可缓存） |
| 角色记录 | 朗读时出现的角色及其分配的发音人 | `characterRecords.json`（文件） |
| 有效发音人 | 当前配置列表里存在的发音人标签 | `fayinren.json`（文件） |
| 性格映射 | 发音人标签 → 显示名/性格的映射 | `fayinren_personality_summary.json`（文件） |

## 二、数据流总览

```
┌─────────────────── 配置列表（前台，DB system_tts_v2）───────────────────┐
│  每个配置项 = 标签(tag) + 性格(personality) + tagName + 启停/分组/排序     │
└──────────────────────────────┬──────────────────────────────────────────┘
                               │ 运行朗读规则时读取（getEnabledListForSort(TAG)）
                               ▼
┌─────────────── 朗读规则 JS（多角色朗读）───────────────┐
│  handleText() 处理文本 → 分配角色 → 写入文件           │
│  characterRecords.json      角色列表（角色名→发音人）   │
│  fayinren.json              有效发音人标签列表          │
│  fayinren_personality_summary.json  性格映射           │
└──────────────────────────────┬────────────────────────┘
                               │ onLoadUI 时读取
                               ▼
┌─────────────── 角色管理插件 JS（mingwuyan）────────────┐
│  角色列表：名字 + 发音人标签(generateVoiceTag)          │
│  用户换标签 = 换发音人 → 写回 characterRecords.json    │
└────────────────────────────────────────────────────────┘
```

## 三、标签/性格与三者的联系

### 1. 标签与性格来自配置列表（DB）

- 每个配置项（TTS 发音人）通过朗读规则配置了标签规则：`tag`（标签名）+ `tagData`（含 `personality`）。
- **tagName 计算**（`TagNameUtils.computeTagName`）：
  1. 调用朗读规则 JS 的 `getTagName(tag, tagData)` 算出名字；
  2. 算不出则回退到规则自带的 `tags` 映射（带 ⚠ 前缀提示）；
  3. 若 `tagData` 中有 `personality` 且名字里未包含，追加到末尾。
  - 结果如：`女青年01` + `晓晓` = `女青年01晓晓`。

### 2. 朗读规则生成角色/性格文件

- 手动点「运行」（`SpeechRuleEditViewModel.debug`）或本次新增的「自动刷新」都会：
  1. eval 朗读规则 code；
  2. 从 DB 取启用 TAG 目标配置（`getEnabledListForSort(SpeechTarget.TAG)`）；
  3. 调 `handleText(样本文本, 配置rules)` → 规则 JS 内部写文件。
- 文件是「配置列表 → 角色列表」的中间层。**前台改配置不会自动更新文件**，必须运行规则才会重新生成——这是「角色列表对不上前台」的根因。

### 3. 角色管理插件读取文件展示

- `onLoadUI` 时读取 `characterRecords.json`（角色）、`fayinren.json`（有效发音人）、`fayinren_personality_summary.json`（性格）。
- 每行角色用 `generateVoiceTag` 把发音人字符串拆成「分类标签 + 性格」两部分上色显示。
- 用户点击发音人标签 → 换发音人 → 写回 `characterRecords.json`。

### 4. 三种「对不上号」场景与根因

| 场景 | 现象 | 根因 |
|---|---|---|
| 前台删了某个标签发音人 | 角色列表仍显示该角色+旧发音人 | 文件未更新（未运行规则） |
| 前台改名/改性格 | 角色列表显示旧名/旧性格 | 同上 |
| 前台换分组/排序 | 角色列表顺序/归属不一致 | 同上（order 变化） |

**共同点**：DB 数据已最新，但「文件中间层」还是旧的，插件 UI 读文件所以显示旧。

## 四、本次修改逻辑

### 修改 1：ToolBoxScreen 自动刷新（app 侧）

文件：`app/src/main/java/com/github/jing332/tts_server_android/compose/ToolBoxScreen.kt`

- 计算「启用配置签名」：所有**启用**配置项的 `(id, tagName, order)` 聚合 hash。
  - 只看启用项：禁用项不参与朗读，变了无需刷新。
- `LaunchedEffect(enabledSig, activeTts.id)`：
  - **首次进入**（`lastSig == null`）或**签名变化** → 后台 `withIO` 执行：
    - 取 `ruleId == "mingwuyan"` 的朗读规则 → `eval` → `handleText(默认样本文本, DB 配置rules)` → 重新生成角色/性格文件。
  - 完成后 `roleFilesReady = true` 才渲染插件 UI（在此之前显示 `LoadingDialog` 遮罩）。
- 效果：
  - 前台改配置 → 打开工具箱时自动重新生成文件 → 角色列表与前台一致；
  - 签名没变（切页等）→ 不运行规则，零开销；
  - LoadingDialog 遮罩避免插件 UI 先读旧文件再重建闪烁，同时缓解 1.3s 卡顿的观感。

### 修改 2：插件 JS ⚠ 提示（角色管理插件侧）

文件：`tts配套文件/ttsrv-plugin-角色管理_桥接试听v7.js`

- 新增 `isVoiceTagValid(tag)`：判断发音人分类标签是否仍在 `fayinrenList`（有效发音人列表，onLoadUI 时读取）。
- `generateVoiceTag` 修改：
  - 标签不存在 → **前缀加红色 ⚠**，且**不显示性格**（性格随发音人消失）；
  - 角色记录本身**保留**（不删除）。
- 效果：删除「女青年01」发音人后，角色列表仍显示该角色，但标签变成「⚠ 女青年01」，性格「晓晓」不再显示。
