# 响度均衡 — 技术实现文档

## 1. 概述

响度均衡系统借鉴 legado 阅读App的 `ReadAloudSpeakerLoudnessManager` + `ReadAloudLoudnessAudioProcessor` 设计，适配 mumu TTS 的多层音频参数架构。

核心目标：在用户手动音量调节（五层乘法叠加）的基础上，追加一层自动增益补偿，按发音人自动平衡响度差异。

## 2. 架构总览

```
TTS 音频流 (InputStream)
    │
    ▼
┌─────────────────┐
│  ExoAudioDecoder │  解码为 PCM 16-bit
└────────┬────────┘
         │
         ▼
┌─────────────────────┐
│ SilenceSkipping (可选)│  静音跳过
└────────┬────────────┘
         │
         ▼
┌─────────────────────┐
│  SonicAudioProcessor │  手动调节：speed/volume/pitch
│  (五层乘法叠加结果)    │  volume = 全局×分组×子分组×插件×单条
└────────┬────────────┘
         │
         ▼
┌──────────────────────┐
│ LoudnessAudioProcessor│  自动增益：按发音人RMS统计补偿
│ (本方案新增)           │  gain ∈ [0.35, 2.4]
└────────┬─────────────┘
         │
         ├──────────────────────┐
         ▼                      ▼
   callback.receive()     loudnessPcmCollector
   (播放)                  (旁路收集最终PCM用于学习)
                              │
                              ▼
                      SpeakerLoudnessManager
                      .analyzePcmAndRecord()
```

## 4. LoudnessAudioProcessor 实现细节

继承 `BaseAudioProcessor`，在 PCM 16-bit 层面施加增益。

### 核心参数

| 参数 | 值 | 说明 |
|------|-----|------|
| MIN_GAIN | 0.35f | 处理器硬下限（约 -9dB），实际不会触及 |
| MAX_GAIN | 2.4f | 处理器硬上限（约 +7.6dB），实际不会触及 |
| RAMP_SAMPLES | 1600 | 增益变化平滑过渡的采样数 |
| SOFT_LIMIT_THRESHOLD | 0.92f | 软限幅开始阈值 |
| SOFT_LIMIT_RANGE | 0.08f | 软限幅压缩范围 |

> **实际增益范围**：上述 MIN/MAX_GAIN 是处理器层面的硬限制。运行时有效范围由 `maxGainProvider`（即 `loudnessMaxGain` 配置项，默认 1.35f）决定：
> - `maxGain = loudnessMaxGain.coerceIn(1.05f, 2.4f)` → 默认 1.35f
> - `minGain = (1f / maxGain).coerceIn(0.35f, 1f)` → 默认 ≈ 0.74f
> - 实际增益范围 **[0.74, 1.35]**（默认配置下），而非 [0.35, 2.4]

### 增益平滑过渡

切换发音人时增益会跳变，用 1600 采样（约 36ms @44100Hz）线性插值过渡：

```kotlin
private fun nextGain(): Float {
    val remaining = rampSamplesRemaining
    if (remaining <= 0) { currentGain = targetGain; return currentGain }
    currentGain += (targetGain - currentGain) / remaining
    rampSamplesRemaining = remaining - 1
    return currentGain
}
```

### 软限幅 (tanh)

增益放大后 PCM 可能超过 [-1, 1] 范围导致硬削波。用 tanh 曲线在 0.92 以上平滑压缩：

```kotlin
private fun softLimit(value: Float): Float {
    val absValue = abs(value)
    if (absValue <= 0.92f) return value  // 0.92 以下完全透明
    val sign = if (value < 0f) -1f else 1f
    val excess = absValue - 0.92f
    val limited = 0.92f + (0.08f * tanh(excess / 0.08f))
    return sign * limited.coerceAtMost(1f)
}
```

## 5. SpeakerLoudnessManager 实现细节

### 发言人 Key 生成

基于发音人的**底层 voice**生成（不依赖 tag、不依赖配置条目 ID），删除重加后 key 不变：

```kotlin
fun speakerKey(config: TtsConfiguration?): String {
    val source = config.source
    return when (source) {
        is PluginTtsSource -> "plugin|${source.pluginId}|${source.voice}"
        is LocalTtsSource -> "local|${source.engine}|${source.voice}"
        else -> "tts|${source.javaClass.simpleName}|${source.voice}"
    }
}
```

> **与 tag 的关系**：响度均衡按 voice 分组学习，**不按 tag**。同一个 tag（如"女青年01"）下若有多个不同 voice 的配置项，每个 voice 各自统计、各自补偿。这是合理的——不同 voice 的实际响度确实不同，而 tag 只是朗读规则的逻辑分类键。详见 `docs/字段关联架构.md` 中 tag 与 voice 的区分。

### 响度分析

分析 PCM 16-bit 数据，计算以下指标：

| 指标 | 说明 |
|------|------|
| activeRms | 有效语音段 RMS（仅 abs(sample) >= VOICE_GATE 的采样） |
| fullRms | 全段 RMS（包含静音段） |
| peak | 峰值 |
| voicedRatio | 语音活动占比 |

**Voice Gate** = 0.012f，低于此值的采样视为静音，不计入 activeRms。

分析支持两种输入：
- `analyzeAndRecord(File)` — 通过 MediaExtractor + MediaCodec 解码音频文件
- `analyzePcmAndRecord(ByteArray)` — 直接分析 PCM byte[]（用于 DefaultResultProcessor 中收集的最终输出 PCM）

### 增益计算

```kotlin
// 1. 取所有已学习发音人的中位数 RMS dB 作为目标响度
val targetDb = medianDb(allStats)

// 2. 计算当前发言人与目标的 dB 差值
val speakerDb = stat.activeRmsDb
val correctionDb = (targetDb - speakerDb)

// 3. 置信度修正
val sampleConfidence = stat.count.toFloat() / (stat.count + 4f)       // 学习次数少时打折
val populationConfidence = ((stats.size - 1).toFloat() / 5f).coerceIn(0.35f, 1f)  // 发音人少时打折

// 4. 最终补偿 dB
val finalDb = correctionDb * sampleConfidence * populationConfidence
    .coerceIn(-MAX_ATTENUATION_DB, dbForGain(maxGain))

// 5. 峰值保护
val peakGuard = if (stat.peak > MIN_RMS) PEAK_LIMIT / stat.peak else maxGain

// 6. 转换为增益
val gain = dbToGain(finalDb).coerceAtMost(peakGuard)
```

**置信度机制的作用：**
- `sampleConfidence`：学习 0 次时 = 0，4 次时 = 0.5，32 次时 ≈ 0.89。防止数据不足时过度补偿。
- `populationConfidence`：只有 1 个发音人时 = 0.35，6 个以上时 = 1.0。发音人太少时中位数不可靠。

### 统计更新（加权平均）

每次新分析结果与旧数据加权平均：

```kotlin
val oldWeight = old.count.coerceAtMost(48)
val newActiveRmsDb = (old.activeRmsDb * oldWeight + newActiveRmsDb) / (oldWeight + 1)
```

旧数据权重上限 48，新数据不断稀释旧数据。手动音量改变后，几段内新数据覆盖旧数据，增益自动修正。

### 数据存储（单一文件，用户可见）

学习数据**只存一份**，就是用户能用文件管理器直接打开的 `Download/chajian/loudness_stats.json`，不再使用 SharedPreferences。文件采用中文易读格式：

```json
{
  "晓晓 (zh-CN-XiaoxiaoNeural)": {
    "发音人": "晓晓",
    "学习次数": 12,
    "平均响度": "-22.7 dB",
    "峰值音量": "68%",
    "语音占比": "62%",
    "最后更新": "2026-08-09 15:30:00",
    "_内部key": "plugin|com.hunyuan|zh-CN-XiaoxiaoNeural"
  }
}
```

**设计要点：**

- **顶层 key**：`displayName (voice)` 格式，如"晓晓 (zh-CN-XiaoxiaoNeural)"，用户一眼能认出是哪个发音人；voice 后缀避免重名发音人冲突
- **字段中文化**：`发音人 / 学习次数 / 平均响度 / 峰值音量 / 语音占比 / 最后更新`，值用 `"-22.7 dB"`、`"68%"`、`"2026-08-09 15:30:00"` 等人类可读格式
- **`_内部key`**：保留原始 `speakerKey`（如 `plugin|com.xxx|voice`），App 重启后从文件加载时用它重建内存 map，保证 `infoFor()` / `needsAnalysis()` 按 `speakerKey` 查找能命中
- **路径**：`/storage/emulated/0/Download/chajian/loudness_stats.json`，与项目其它模块一致（朗读规则 JS `getFile()`、插件缓存 `PluginManager.CACHE_BASE_DIR` 同目录）
- **读写时机**：`init()` 启动时加载一次到内存；`persistLocked()` 每次学习后整体覆盖写入；`reset()` 直接删文件
- **失败容错**：文件读/写失败仅记录日志，不影响播放（读失败回退空数据，写失败内存缓存仍有效）
- **向后兼容**：`parse()` 同时识别中文新格式与旧版英文格式（老用户 SharedPreferences 里的数据若已被清空则从头学，无历史包袱）

限制：最多 240 个发音人，按 `updatedAt` 降序保留；每个发音人最多学习 32 次。

## 6. DefaultResultProcessor 集成

### Pipeline 构建

```kotlin
val pipelines = listOf(
    if (context.cfg.silenceSkipEnabled()) skipAudioProcessor else null,
    sonicAudioProcessor,        // 手动调节
    loudnessAudioProcessor      // 自动增益（始终启用）
).filterNotNull()
```

### 增益设置

```kotlin
val loudnessInfo = SpeakerLoudnessManager.infoFor(config)
loudnessAudioProcessor.setGain(loudnessInfo.gain)
```

### PCM 收集与学习

```kotlin
val needsLoudnessAnalysis = SpeakerLoudnessManager.needsAnalysis(config)
val loudnessPcmCollector = if (needsLoudnessAnalysis) ByteArrayOutputStream() else null

// handle() 中收集最终输出 PCM（processor.output 的副本）
if (loudnessPcmCollector != null && out.hasRemaining()) {
    val dup = out.duplicate()
    while (dup.hasRemaining()) loudnessPcmCollector.write(dup.get())
}

// 播放完成后异步分析
if (loudnessPcmCollector != null && loudnessPcmCollector.size() > 0) {
    SpeakerLoudnessManager.analyzePcmAndRecord(pcmBytes, config)
}
```

**关键设计：分析的是 Sonic + LoudnessProcessor 之后的最终输出 PCM。**

这样做的理由：
- 用户听到的就是这个 PCM，分析它最准确
- 手动音量调节变化时，新数据自然覆盖旧数据
- 删除重加发音人（手动音量不同）时，几段内自动修正

### 流式/非流式兼容

两种模式都经过 `decode()` → `handle()` 路径，LoudnessAudioProcessor 和 PCM 收集逻辑共用，无需区分。

## 7. 与手动调节的协同

### 音量

```
最终音量 = Sonic.volume (五层手动乘法) × LoudnessProcessor.gain (自动补偿)
```

手动调大方向，自动补细节。两层独立工作，互不干扰。

### 语速 / 音调

不涉及响度均衡，完全由 Sonic 处理，保持五层乘法叠加架构不变。

## 10. 性能

- 响度分析异步进行，不阻塞播放
- 每个发音人学满 32 段后停止分析（`needsAnalysis` 返回 false），零开销
- LoudnessAudioProcessor 每采样 1 次乘法 + 1 次 tanh（仅超阈值时），性能可忽略
- PCM 收集仅在需要学习时启用，学满后不收集

## 11. 与 legado 的差异

| 方面 | legado | mumu |
|------|--------|------|
| 手动音量调节 | 无 | 五层乘法叠加 |
| 分析对象 | 原始音频文件 | 最终输出 PCM（手动+自动之后） |
| 发言人 Key | 引擎类型\|引擎值\|音色ID\|发言人名 | 插件ID\|voice / 引擎\|voice |
| 开关 | 用户可开关 | 始终开启 |
| 增益施加 | ExoPlayer AudioProcessor | AudioProcessingPipeline（与 Sonic 共用） |
| PCM 收集 | 不收集（直接分析文件） | 旁路收集最终输出 PCM |
| 分组音频参数 | 无分组概念 | 有分组/子分组，已删除其音频参数 UI 入口 |
