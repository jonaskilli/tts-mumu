# 兜底体系架构

> 目标：当角色识别失败、发音人获取失败、播放重试失败时，系统按性别自动回退到兜底发音人，保证朗读不中断。
> 关联文件：
> - 朗读规则：`tts配套文件/多角色朗读2.87【加速版+1修复2.2】同步显示名.js`
> - app端备用注入：`lib-tts/src/main/java/com/github/jing332/tts/TtsRepository.kt`
> - app端重试切换：`lib-tts/src/main/java/com/github/jing332/tts/synthesizer/AbstractMixSynthesizer.kt`
> - 事件定义：`lib-tts/src/main/java/com/github/jing332/tts/synthesizer/event/NormalEvent.kt`
> - 日志显示：`app/src/main/java/com/github/jing332/tts_server_android/service/systts/SystemTtsService.kt`
> 状态：**已实施**（2026-08-08）

---

## 一、整体架构

兜底体系分两层：**朗读规则层（JS）** 和 **app端备用层（Kotlin）**。

```
┌─────────────────────────────────────────────────────────────┐
│  朗读规则层 (JS) — 角色分配阶段                              │
│                                                             │
│  AI分析角色 → 能识别?                                        │
│    ├─ 是 → assignVoice 按性别分配发音人                      │
│    └─ 否 → 按性别走兜底 tag                                  │
│         ├─ 男 → duihuaA                                     │
│         ├─ 女 → duihuaB                                     │
│         └─ 未知/空 → duihua                                 │
└──────────────────────────┬──────────────────────────────────┘
                           │ 返回 tag
                           ▼
┌─────────────────────────────────────────────────────────────┐
│  app端备用层 (Kotlin) — 播放重试阶段                         │
│                                                             │
│  按 tag 取发音人播放                                         │
│    ├─ 成功 → 正常播放                                        │
│    └─ 失败重试3次                                            │
│         ├─ 普通发音人 → 同标签备用 → 性别兜底                │
│         ├─ 兜底发音人(duihuaA/B/duihua) → 无备用，记录错误日志│
│         └─ 音效(localSound) → 无备用，记录错误日志            │
│         全部失败 → 按restartOnMaxRetryMode处理               │
└─────────────────────────────────────────────────────────────┘
```

## 二、朗读规则层（JS）

### 2.1 性别取值

gender 字段共5种可能值：

| gender值 | 来源 | 说明 |
|---------|------|------|
| `"男"` | MAIN_ROLES_CONFIG、BATCH_ROLES、API返回 | 男声 |
| `"女"` | MAIN_ROLES_CONFIG、BATCH_ROLES、API返回 | 女声 |
| `"特殊"` | BATCH_ROLES(特殊男/女)、SPECIAL_ROLES(括号1/4) | 特殊 |
| `"特"` | SPECIAL_ROLES(括号2/3) | 特殊(简写) |
| `""`（空） | analyzeCharacterFallback、voteBatchAliasAnalyzeResult | 密钥失效/分析失败 |

### 2.2 兜底分配逻辑

4处返回兜底 tag 的位置，逻辑统一为：

```javascript
analysis.gender === "男" ? "duihuaA" : analysis.gender === "女" ? "duihuaB" : "duihua"
```

| 位置 | 行号 | 触发条件 |
|------|------|---------|
| 角色无法识别 | ~1981 | newCharacterName === "未知" |
| 无可用发音人 | ~1988 | assignVoice 返回 null |
| 发音人失效且无可用 | ~2012 | voice失效 + assignVoice返回null |
| 角色voice为空且无可用 | ~2043 | voice为空 + assignVoice返回null |

### 2.3 兜底日志

每处兜底分配都输出 `console.log`（显示在日志栏，前缀 `[SpeechRule]`）：

```
[SpeechRule] 【兜底分配】角色无法识别(性别:女)→duihuaB | 文本:他轻轻说道
[SpeechRule] 【兜底分配】无可用发音人(角色:张三,性别:男)→duihuaA
[SpeechRule] 【兜底分配】发音人失效且无可用(角色:李四,性别:未知)→duihua
[SpeechRule] 【兜底分配】角色voice为空且无可用(角色:王五,性别:女)→duihuaB
```

### 2.4 失败降级

两处"AI分析失败"的兜底，gender 统一为空（不再随机分配男女声）：

| 位置 | 行号 | 触发条件 | 原 behavior | 现 behavior |
|------|------|---------|------------|------------|
| analyzeCharacterFallback | ~2862 | 密钥失效/分析失败 | 随机男女 | gender="" → duihua |
| voteBatchAliasAnalyzeResult | ~608 | 多API投票无有效结果 | 随机男女 | gender="" → duihua |

### 2.5 tags 定义

```javascript
tags: {
    narration: "旁白",
    duihua: "对话",        // 中性兜底
    duihuaA: "男",         // 男声兜底
    duihuaB: "女",         // 女声兜底
    "括号1": "【】括号发音人",
    "括号2": "在线音效",
    "括号3": "「」括号发音人",
    "括号4": "『』括号发音人",
    localSound1~990: "本地音效N",
    // + GENSHIN_CHARACTERS 动态生成的角色 tag
}
```

## 三、app端备用层（Kotlin）

### 3.1 备用配置注入（TtsRepository.kt）

`getAllTts()` 启动时为每个发音人配置项计算 `standbyConfig`：

```
同标签备用（精确匹配 target+tagRuleId+tagName）
    ↓ 找不到
性别兜底（按原tag前缀判断 → duihuaA/B/duihua）
    ↓ 找不到
null（无备用）
```

**性别兜底判断逻辑**（按原 tag 前缀）：

| 原 tag 前缀 | 判断 | 兜底到 |
|------------|------|--------|
| `男`开头（男主、男青年、男中年、男老年、男童） | startsWith("男") | duihuaA |
| `少年`开头 | startsWith("少年") | duihuaA |
| `特殊男` | == "特殊男" | duihuaA |
| `女`开头（女主、女青年、女中年、女老年、女童） | startsWith("女") | duihuaB |
| `少女`开头 | startsWith("少女") | duihuaB |
| `特殊女` | == "特殊女" | duihuaB |
| 其他（括号1-4、narration、localSound等） | else | duihua |

**特殊处理**：
- duihuaA/B/duihua 自身跳过性别兜底层（避免自引用）
- duihuaA/B/duihua 的 `standbyConfig` 强制为 null（失败直接报错，不再找备用）

### 3.2 重试切换（AbstractMixSynthesizer.kt）

播放失败时的重试流程：

```
第1次失败 → retry()
  ├─ 有 standbyConfig 且达到触发阈值(默认3次) → 切换到 standbyConfig
  └─ 无 standbyConfig 或未达阈值 → 重试同一发音人
      ↓
重试超限 (retries > maxRetries)
  ├─ 兜底发音人(duihua/duihuaA/duihuaB)或音效(localSound) → 记录错误日志
  └─ 按 restartOnMaxRetryMode 处理：
      ├─ 模式0：静音+继续（默认）
      ├─ 模式1：直接重启
      └─ 模式2：静音+重启
```

**报错只记录日志，不改变播放行为**——是否静音、是否重启由用户的 `restartOnMaxRetryMode` 决定。

### 3.3 备用切换日志

切换备用时发送 `NormalEvent.StandbyTts` 事件，携带 `fromTag`、`toTag`：

```
使用备用发音人：女青年01 → duihuaB（重试失败兜底）
```

### 3.4 兜底/音效失败日志

兜底发音人或音效重试超限时，发送 `ErrorEvent.Request`：

```
功能标签(duihuaB)兜底发音人重试失败，已跳过
```

## 五、用户配置要求

### 必须配置

在 app 端系统TTS列表里，配置以下3个标签的发音人（**正常配置即可，无需勾选"备用"**）：

| 标签 | 建议发音人 | 用途 |
|-----|-----------|------|
| duihuaA | 任意男声 | 所有男声tag的兜底 |
| duihuaB | 任意女声 | 所有女声tag的兜底 |
| duihua | 任意中性/稳定发音人 | 括号/旁白/音效/未知性别的兜底 |

### 可选配置

- 同标签备用：给特定发音人配 `isStandby=true` 的同标签备用，优先于性别兜底
- `standbyTriggeredRetryIndex`：备用触发阈值（默认3次）
- `restartOnMaxRetryMode`：重试超限处理方式（默认0=静音继续）

## 六、已删除的功能

### 全局备用发音人（已删除）

原 `standbyGlobalTtsId` 配置允许设置一个全局备用发音人，作为同标签备用和性别兜底之后的最后兜底。

**删除原因**：性别兜底层（duihuaA/B/duihua）已覆盖所有场景，全局备用冗余且增加复杂度。

**删除范围**：
- `SynthesizerConfig.kt` — `globalStandbyId` 字段
- `TtsRepository.kt` — 全局备用查询+注入逻辑
- `SystemTtsConfig.kt` — `standbyGlobalTtsId` 配置项
- `SysTtsConfig.kt` — `standbyGlobalTtsId` 属性
- `SystemTtsService.kt` — 传入 `globalStandbyId`
- `SysttsSettingsScreen.kt` — UI设置项
- 7个语言文件的 `systts_global_standby_tts*` 字符串

## 七、关键设计决策

### 7.1 为什么兜底发音人不挂备用？

兜底发音人（duihuaA/B/duihua）本身就是"最后的兜底"。如果连兜底都失败，说明系统已无计可施，再找备用没有意义。此时记录错误日志，按用户的 `restartOnMaxRetryMode` 处理即可。

### 7.2 为什么报错不直接跳过？

报错只是日志记录，**不改变播放行为**。是否静音、是否重启，由用户的 `restartOnMaxRetryMode` 决定。这样报错和播放控制解耦，用户保持对播放行为的控制权。

### 7.3 为什么音效(localSound)失败也报错？

音效是本地音频文件，无法用发音人兜底。失败时记录错误日志，让用户知道哪个音效文件有问题。

### 7.4 为什么括号1-4不报错？

括号1-4是独立功能标签（【】发音人、〖〗音效、「」发音人、『』旁白），不是兜底发音人。它们失败时走原有逻辑（同标签备用 → restartOnMaxRetryMode），不额外报错。

### 7.5 为什么随机gender改为空？

原来密钥失效/分析失败时，用 `Math.random()` 随机分配男女声，会导致：
- 本该中性的句子被随机分到男/女声
- 可能引发无谓的备用切换（随机男声→播放失败→切备用）

改为空 gender 后，统一走中性 `duihua`，行为一致且可预测。
