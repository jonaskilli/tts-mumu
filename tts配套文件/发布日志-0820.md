## TTS-Server v1.28 更新日志（2026-08-20）

---

### 🔥 核心修复：朗读语速双重生效问题

**问题描述**：部分 TTS 插件（如纳米 AI 等）会把语速参数发给服务端变速，但本机 Sonic 同时也会再用同一份配置项值做本地变速，导致朗读时语速被乘了两次（配置项 1.5 实际听感约 2.25 倍）

**修复方案**：新增插件级「参数处理」开关，让框架知晓插件是否已消费该参数，朗读时本机自动跳过对应处理

| 开关 | 效果 |
|---|---|
| **语速已由插件处理** | 朗读时 Sonic 不再叠加语速，仅保留重采样 |
| **音量已由插件处理** | 朗读时 Sonic 不再叠加音量 |
| **音调已由插件处理** | 朗读时 Sonic 不再叠加音调 |

**使用场景**：
- 纳米 AI 等消费 rate 插件 → 勾选「语速已由插件处理」→ 朗读语速准确
- 普通插件不消费参数 → 不勾选 → Sonic 正常兜底变速（行为不变）
- 试听路径不受影响，两种插件试听表现一致

**配置入口**：插件管理 → 点击插件卡片 → 音频参数 → 三个开关分别内联在语速/音量/音高滑块下方（详见下方「插件音频参数可用性」节）

### 🔧 音频参数基础修复（承接 v1.27）

- **根因**：插件 source 级参数（编辑插件时的滑块，默认 1.0）直接覆盖配置项音频参数，导致配置项调整无效
- **修复**：改为相乘叠加体系，最终值 = source 级 × 配置项级 × 子分组级 × 分组级 × 全局级
- **适用场景**：
  - source 滑块 = 1.0（默认）→ 配置项参数完整生效
  - source 滑块 = 1.5 + 配置项语速 = 1.2 → 实际 1.8
  - source 滑块 = 0（跟随）→ 只用叠加值

## 补充：8.19 复核后新发现的五项修改

> 以下内容为 8.19 主体功能完成后，复查/实测中补提出的漏洞修复，补充记录于此。

### ① 失效配置项交互重构

- **问题**：主界面搜索框选「失效项」后，多来源弹窗中间一块用了独立背景色，色差突兀；且该入口藏在搜索框里不直观。
- **修复**：
  - 失效配置项移出搜索框；当存在失效项时，主界面顶栏「多选」键**左侧**出现红色警告按钮（⚠），点击在配置列表中定位并定位到各失效来源；
  - 每个失效来源以列表行呈现：箭头置于**最左侧**（与配置列表分组一致），整行（点名称或箭头）均可点击展开；插件名后以小字括号显示项数（如「旧插件A（12）」），插件名过长自动省略号截断；
  - 展开后以卡片化样式列出该来源下具体失效配置项名称，整齐美观；每行提供「切换插件」按钮（文案由"切换为其他插件"精简），进入目标插件选择完成批量替换。

### ② 大批量配置导入进度反馈

- **问题**：导入几百个配置项时解析/写入期间界面无反馈，用户以为卡住而误退。
- **修复**：导入遮罩 <300ms 快速导入直接跳过（避免一闪而过），超时显示；遮罩内先显示「正在解析配置项…请稍候」，插入阶段显示进度条「已导入 X / Y 项」；完成后照常提示「已导入 N 项」。
- **说明**：本次优化的是过程可见性，实际写入耗时未变，但用户不再因无反馈误退。

### ③ 备份恢复：UI 偏好丢失

- **问题**：设置中「交换试听和编辑按钮」、主界面「试听文本」等偏好，恢复备份后被默认值覆盖。
- **根因**：这些偏好处于默认值（或改回默认）时，DataSaver 不会在 `app.xml` 写出对应节点，备份包缺键，恢复时被默认覆盖。
- **修复**：备份前调用 `persistAppConfigForBackup()`，用原生 `SharedPreferences.edit().commit()` 强制落盘当前真实值（涵盖交换按钮、试听文本、自动检查更新、排除最近任务、Edge DNS、标签/名称长度限制、下拉数量等），确保备份包始终含它们。

### ④ 插件音频参数：「由插件处理」开关可用性

- **问题**：插件是否消费 `rate`/音量/音调，用户肉眼看不出来，无法按需勾选。
- **本次改动**：三个开关从底部集中区改为分别内联到对应参数滑块（语速/音量/音高）下方，并各加一行说明文字，解释「勾选后本机不再叠加该处理」，便于识别该插件是否需要特殊配置。
- **待办**：自动判断插件是否消费参数（如检索插件 JS 是否发送 rate/volume/pitch）尚未实现，目前仍需用户/维护者手动判断后勾选。

### ⑤ 转发器与播放性能优化

- **问题**：使用「直连随机」朗读规则、不开转发器时，点击播放到出声有明显等待。
- **修复**：
  - 转发器默认引擎由原「手机系统 ai service」改为「当前使用的 TTS」（App 的朗读规则/角色管理/插件），导入阅读后效果与直连一致（8.19 既有功能）；
  - 转发器合成由跨进程 `androidTts.init(包名)` Binder 调用改为进程内直接调用 `MixSynthesizer.global`，路径更短（8.19 既有功能）；
  - **服务启动预热引擎**（e0fbd01 本轮补充）：`SystemTtsService.initManager` 时在后台预热 `MixSynthesizer.global` 及所有已启用插件引擎，避免首播/开转发器现场 eval 大体积插件 JS；`MixSynthesizer.init()` 幂等、引擎带缓存，后续播放直接命中缓存；**预热动作保留，但不再打印预热明细日志**（如 `preloaded plugin engine: xxx`），启动日志更干净，仅预热失败时才告警。
- **说明**：与 hunyuan 分支对比，进程模型一致（均主进程、`global` 单例共享），cnb_work 因有预热且调用路径更短，首播与后续播放均不慢。

## 补充：本次打包前三项修改

> 仓库 `cnb_work` 推送 `mumu_tts_github` 后 CI 验证通过、并触发 release 构建的这轮改动，共三项。

### Ⅰ 搜索栏「失效项」筛选移除

- **背景**：失效配置项已在主界面顶栏以红色警告按钮 + 详情弹窗（可逐来源展开、切换其他插件，见上方 8.19 五项①）处理，搜索框里再保留一个「失效项」筛选入口属于重复、且藏得深不直观。
- **改动**：
  - 删除 `SearchType.INVALID` 枚举项及 `filterList` 中对应分支；
  - 搜索栏关闭时不再做 `INVALID → NAME` 的复位逻辑；
  - 移除已无引用的字符串 `invalid_items`（中/英）；
- **效果**：搜索框只剩「名称 / 分组」两类筛选，失效项统一走顶栏警告按钮交互。

### Ⅱ 大批量配置导入进度反馈（修正实现）

- **问题**：导入几百个配置项时，从点「确定」到「已导入 N 项」之间解析 + 单事务写库 + 列表重组耗时明显，用户长时间看不到反馈、误以为卡死。
- **最终实现**（修正上一版记录）：
  - 导入开始即显示**单一「正在导入…」遮罩**，读取与解析/写库同处一个状态机，全程只此一个遮罩，不再出现「底部面板闪一下 + 读遮罩 + 写遮罩 + 结果」多层叠加；
  - **外部文件导入（autoImport + 预设路径/URL）跳过底部面板**，直接进入遮罩，完成后弹出结果（如「已导入 N 项配置列表」）；
  - 四类导入（配置列表 / 插件 / 替换规则 / 朗读规则）统一复用该状态机，结果以 AlertDialog 统一弹出；
- **识别提示统一（本轮补充）**：
  - 内部导入与外部（文件/URL）导入最终都走同一条 `doAutoImport` 自动识别流程，**识别只发生一次**；
  - **不再弹出「已自动识别为 XXX」toast**：识别成功直接跳入导入页，不打扰；
  - 识别不出类型时，统一以错误对话框展示可读原因（不再只给一句「未识别到有效配置」）：空内容提示「内容为空，请检查文件/剪贴板是否为空」；类型无法判断提示「无法判断配置类型：未匹配到配置列表 / 插件 / 朗读规则 / 替换规则的特征字段…」；与 JSON 解析失败提示样式一致、可滚动/复制；
  - 外部导入原本独有的「识别不出就弹手动选类型」对话框已移除，行为改为与内部一致（交给统一流程识别，不出则显示原因），并清理了相关死代码；
- **说明**：优化的是过程可见性，实际写入耗时未变，但用户不再因无反馈而误退或焦虑。

### Ⅲ 插件音频参数对话框精简

  - **去重标签**：复选框标签由「语速已由插件处理」简化为「语速」（避免与小标题重复）；
  - 说明文案精简为：「勾选后本机不再叠加该项，交由插件处理，避免双重生效。试听不受影响。」；

### Ⅴ 批量试听分组保存：采样率固定 16000 修复

- **问题**：在插件 TTS 编辑界面「声音栏」批量勾选发音人并试听分组后点「保存」，批量插入的声音 `audioFormat.sampleRate` 固定为 16000（`BasicAudioFormat` 默认值，且批量保存路径未主动解析采样率），导致按 44100/24000 等真实采样率输出的引擎被错误标记为 16000，播放时被 Sonic 变速/重采样而异常。
- **改动**（`PluginTtsUI.kt` 批量保存）：
  - 每个被保存的声音优先调用 `engine.getSampleRate(locale, voice)`（即插件 JS 的 `EditorJS.getAudioSampleRate`）读取采样率，写入该声音的 `audioFormat.sampleRate`；
  - 若 JS 未实现/返回 null，则**实际合成一次该声音**，从返回音频字节用 `AudioDecoder.getSampleRateAndMime` 解析真实采样率（复用试听逻辑），避免落入 16000 默认值；
  - 同步补 `isNeedDecode`（`engine.isNeedDecode`），取不到时沿用当前配置；
  - 合成失败时退回当前配置值，不强制改坏。
- **说明**：多数插件实现了 `getAudioSampleRate`，走快速路径不额外合成；仅 JS 未实现的插件才实际合成兜底。

### Ⅵ 试听分类体验完善（批量给插件声音试听后分子分组）

- **问题**：批量试听分类（`AuditionDialog` 中逐个试听并分配分类）流程存在多处不便：弹窗不显示当前发音人名字与进度；回看上一个声音时不知道是否已分类；没听清无法重播、合成失败无法重试只能关弹窗重开；试听时已从真实音频解析出的采样率被丢弃，批量保存时又重复合成一遍。
- **改动**：
  - **AuditionDialog**（`AuditionDialog.kt`）：
    - 顶部显示当前声音名（主色 `titleMedium`）+ 进度序号「12/50」（多于 1 个声音时）；
    - 显示「已分类：xx」——回看时可知是否分过类，重选分类 chip 即覆盖改派（`onCategoryAssigned` 本就是覆盖语义）；
    - 新增「重播」按钮：`retryKey` 计数驱动 `LaunchedEffect(systts, retryKey)` 重启合成，没听清重听、失败重试（重试成功后分类按钮恢复显示）；
    - 新增 `onSampleRateResolved` 回调：解析出真实采样率后回传调用方缓存；
  - **采样率缓存复用**（`PluginTtsUI.kt`）：新增 `voiceSampleRateCache`（发音人→采样率），批量保存采样率优先级变为 **试听缓存 → JS `getAudioSampleRate` → 实际合成解析**，试听过的声音保存时零额外请求；
  - **分类标签常量化**（`lib-compose` `AppSelectionDialog.kt`）：新增公共 `VoiceCategories`（`ALL`/`ROWS`），试听分类弹窗与声音列表长按分类菜单共用，消除两处硬编码不同步的隐患（两处内容此前一致：默认 + 女童/少女/女青年/女中年/女老年/男童/少年/男青年/男中年/男老年）；
  - **分类标签来源厘清（两类标签、两个来源）**：
    - **配置项标签**：来自**插件 JS**（`EditorJS.getTagName` 等），即配置项里各项内容的标签是按插件定义生成的，与朗读规则无关；
    - **试听分类标签**：来自**朗读规则 JS**，下方 Ⅶ 节详述；
    - 二者来源不同，此前容易混淆，现已在代码中分别归属各自引擎，避免串味。
  - **试听分类标签依据朗读规则生成**（`SpeechRuleEngine.kt` + `PluginTtsUI.kt` 批量保存）：
    - 朗读规则 JS 新增可选钩子 `getCategoryTag(category, seq)`：返回「某分类下第 seq 个声音」应使用的 tag，**每套规则可实现自己的逻辑**（映射到已有角色 tag、不同序号格式等）；
    - 未实现该钩子或返回空时，回退默认「分类名+两位序号」（如「女青年01」），行为与此前一致；
    - 标签名（tagName）同样优先走规则的 `getTagName`（各规则自己的取名逻辑），取不到再用 tag 本身；未实现 `getTagName` 时回退 tags 内显示名（与原伴生方法行为一致）；
    - 性能：规则引擎改为循环外 `eval()` 一次并在批量保存全程复用，不再每个声音重复执行数千行 JS；

### ② 新增「旁白」分类（不带序号）

- **问题**：2.87 直连朗读规则 `SPECIAL_ROLES` 中「对话旁白」对应 age 字段 `旁白`，但它是单一角色、不应像其他分类那样带两位序号（如 `旁白01`）。
- **改动**（`VoiceCategories.ALL` 追加 `旁白`；`PluginTtsUI.kt` 分类标签生成逻辑特判）：
  - `ALL` 在特殊男/特殊女之后追加 `旁白`，`ROWS` 补 `listOf("旁白")`；
  - 保存生成标签时，当 `category == "旁白"` 直接用 `旁白` 本身，不调规则 `getCategoryTag`、也不拼两位序号；其余分类仍按「分类名+两位序号」（如 `女青年01`、`男主01`）生成；
  - 显示名 `tagName` 沿用到 `旁白`，与规则底层名一致。

### ③ 去掉「直选标签」（不再从朗读规则加载全部标签）

- **问题**：8.19 在试听弹窗加了「指定标签」区，从朗读规则 `SpeechRule.tags` 拉出全部标签供直接点选（直选标签优先级高于分类生成）。实际使用只走固定分类即可，从规则拉标签反而干扰、且与「分类决定标签、朗读规则只决定显示名」的定位不符。
- **改动**（移除整条直选标签链路）：
  - `AuditionDialog.kt`：删除 `availableTags`/`onTagAssigned`/`assignedTag` 三参数、`指定标签` UI 区、回显里的标签部分；
  - `PluginTtsUI.kt`：删除加载 `SpeechRule.tags` 的 `LaunchedEffect`、状态 `voiceTagMap`/`availableTags`、试听调用处的直选传参、保存快照 `tagMapSnapshot` 与 `directTag` 优先分支；
  - 保存逻辑只剩两条路径：选了分类（生成「分类名+序号」，旁白无序号）→ 走标签；没选 → 按规则 `tagKeys` 循环分配；
  - **标签来源澄清**：分类决定标签值（`分类名+序号`），朗读规则仅通过 `getCategoryTag`/`getTagName` 决定底层名格式与显示名，删除直选标签后标签来源完全由固定分类决定，不再混入规则自定义标签。

### ④ 试听弹窗不再显示试听文本

- **问题**：弹窗里把测试文本原样显示出来属于冗余（文本就是固定测试话，用户点试听是为听声音，不是看自己刚输入的话；失败时还会被错误文案顶替）。
- **改动**（`AuditionDialog.kt`）：正常试听时隐藏文本块，仅失败时显示红色错误文案；测试文本本身仍用于合成输入，UI 不渲染。弹窗更紧凑。

### ⑤ 声音选择弹窗布局重排与边距对齐

- **问题**：点击声音栏弹出的 `AppSelectionDialog`，顶部「标题 + 等待分类开关 + 搜索🔍 + 自动下一个开关」挤在一起，搜索图标夹在两个开关中间，且开关无文字标签不知所指；列表项被加了 8dp 内边距后，反而比标题/开关往里缩、三块左边缘不对齐。
- **改动**（`AppSelectionDialog.kt` + `lib-compose` 字符串资源）：
  - **搜索按钮移出开关群**：标题行改为「标题占左（weight 1f）+ 搜索 IconButton 独占最右」，不再夹在中间；
  - **开关下移独立成行**：「等待分类」「自动下一个」两个开关移到列表上方一行，各带文字标签（新增字符串 `wait_for_category`/`auto_next`，含中/英），不再无名挤在标题里；
  - **边距对齐**：列表行与开关行去掉误加的 8dp 水平内边距，三块（标题/开关/列表）左边缘统一对齐到 `AppDialog` 内容区 12dp 边；行内文字 16dp 留白提供呼吸，高亮块贴内容边（Material 列表风格）；
  - 该组件为通用弹窗，其他调用方未传这两个开关时不显示开关行，不受影响。
