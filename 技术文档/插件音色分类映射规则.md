## 二、映射逻辑

### 2.1 预处理（归一化）

插件原始分类名先经过以下预处理：

```kotlin
var s = raw.trim()
    .removeSuffix("通用")    // 去除通用后缀
    .removeSuffix("发音人")  // 去除发音人后缀
    .removeSuffix("音色")    // 去除音色后缀
    .trim()
    .replace("女性", "女")   // 女性 → 女
    .replace("男性", "男")   // 男性 → 男
```

**示例**：
- `女性青年通用` → `女青年`
- `男性童声` → `男童`
- `开朗行动系·机灵·鬼点子型` → `开朗行动系·机灵·鬼点子型`（无变化）

### 2.2 关键词匹配

预处理后的字符串，按**最长关键词优先**原则匹配：

```kotlin
TAG_KEYWORDS.filter { s.contains(it) }.maxByOrNull { it.length }
```

**为什么最长优先**：避免 `少女` 被 `女青年` 误命中，或 `男童` 被 `儿童` 误命中。

**示例**：
| 预处理后 | 命中关键词 | 最终映射 |
|----------|-----------|---------|
| `女青年` | `女青年`（3字） | `女青年` ✓ |
| `女性青年` | `女青年`（3字，含"女性→女"归一） | `女青年` ✓ |
| `女童声线` | `女童`（2字） | `女童` ✓ |
| `开朗行动系` | 无 | `null`（原样入库） |

### 2.3 无法映射的处理

若预处理后字符串**不包含任何标准关键词**，则 `mapTagCategory()` 返回 `null`：

- 子分组名：**插件原名原样入库**
- 朗读标签：**不生成**（`SpeechRuleInfo` 为空）

**典型场景**：jread 转换过来的性格类分类（如 `开朗行动系·机灵·鬼点子型`、`古灵精怪·灵动型`）。

## 三、标签生成规则

映射成功后，按以下规则生成朗读标签（`SpeechRuleInfo.tag`）：

### 3.1 普通分类（补零）

```kotlin
category + String.format(Locale.US, "%02d", seq)
```

| 分类 | 序号 | 标签 |
|------|------|------|
| 女童 | 1 | `女童01` |
| 女青年 | 15 | `女青年15` |
| 男老年 | 3 | `男老年03` |

### 3.2 特殊分类（不补零）

以下分类**不补零**，直接拼接序号：

```kotlin
val NO_ZERO_PAD_PREFIXES = setOf("男主", "特殊男", "特殊女")
category + seq.toString()
```

| 分类 | 序号 | 标签 |
|------|------|------|
| 男主 | 1 | `男主1` |
| 特殊女 | 20 | `特殊女20` |
| 特殊男 | 3 | `特殊男3` |

**为什么这些不补零**：男主角/特殊角色通常数量较多（可能超过 99 个），补零后 `男主01`…`男主200` 排序反而不如 `男主1`…`男主200` 自然。

### 3.3 旁白（无序号）

`旁白` 为单一角色分类，不带序号：

| 分类 | 序号 | 标签 |
|------|------|------|
| 旁白 | - | `旁白` |

## 六、扩展指南

如需新增标准人群分类（如 `AI助手`、`虚拟主播` 等新类型），只需：

1. 在 `TAG_KEYWORDS` 列表中添加关键词（注意**按长度降序**排列，保证最长优先）
2. 如需特殊补零规则，在 `NO_ZERO_PAD_PREFIXES` 中添加前缀
3. 更新本文档「一、标准人群关键词表」

```kotlin
private val TAG_KEYWORDS = listOf(
    // 新增示例（放在合适位置，保持长度降序）
    "AI助手",  // 假设新增
    // ... 现有列表
)
```
