# 角色管理 入口可达性审计（2026-09-14）

> 前一篇《角色管理 v10 复刻差异审计》是**函数语义对照**——两边对应函数的逻辑是否一致。
> 这次换一个方向查：**从用户能点的东西出发，逐条确认能不能走通。**

## 0. 为什么还要查一遍

语义审计有个天然盲区：**函数在 ≠ 用户点得到**。

- 函数写得再对，UI 上没有入口绑它 ⇒ 用户永远看不见（死代码）；
- 入口在但动作只接了一半 ⇒ 点了卡住或走向意外分支（半接通）；
- v10 有的入口，Kotlin 整条没搬 ⇒ 功能缺失。

这三类问题，**函数级对照抓不到**——因为函数本身没问题。

## 1. 方法

| 侧 | 做法 |
|---|---|
| v10 | 抓全部 **171 个 `function` + 45 个箭头函数**，筛出 UI 绑定（`setOnClickListener` / `onClick:` / `show*Dialog` 调用链），理出入口树 |
| Kotlin | 抓 `onClick` / `clickable` / `combinedClickable` / `DropdownMenuItem`；另写脚本扫全仓 **945 个函数定义**，统计「定义数 vs 引用数」，找出无调用方者 |
| 比对 | 按「未搬入口 / 死代码 / 路径变化 / 有意合并」四类归档 |

## 2. 结论总览

| 类别 | 数量 | 性质 |
|---|---|---|
| **A 未搬入口** | 1 | 功能缺失（已知，待拍板） |
| **B 死代码** | 5 | 有实现、无入口 |
| **C 入口路径变化** | 3 | 功能可达，用户路径变了 |
| **D 有意合并** | 1 组（7 → 1） | 非问题 |

**没有发现「入口在但动作半接通」的新案例**（唯一已知隐患是添加角色模式的音频参数回落，正文 §8 附注）。

## 4. B 类 · 死代码（有实现、没有任何入口）

| 函数 | 位置 | 判定 |
|---|---|---|
| `removeAlias` | `CharacterRecordsFile` | 调用点 **0** |
| `unbindVoice` | `CharacterRecordsFile` | 调用点 **0**。⚠️ 语义与 v10 **相反**——它会清空该 tag 下**全部**角色的 voice，而 v10 删除流程**从不**碰角色 voice。将来谁把它接上入口就是踩雷 |
| `deleteBook`（单数） | `CharacterRecordsFile:480` | 调用点 **0**。单本删书已由 `deleteBooks`（复数 `:567`）覆盖——`KeyManagerScreen:1715` 传 `setOf(name)` 走的正是复数版 |

### ⚠️ 重要提醒：这 5 个不会让 CI 变红

Kotlin 对未使用的 `private` 只发**告警**，对 `public` 什么都不说。
⇒ **「CI 绿」不能推出「没有死代码」**。这也是这次要单独查的原因。

## 5. C 类 · 入口路径变化（可达，但路径与 v10 不同）

| 功能 | v10 入口 | Kotlin 入口 | 影响 |
|---|---|---|---|
| **发音人管理**（标记 / 删除） | 角色行右侧 **⋮** → `showVoiceManageDialog` | 换声弹窗**候选行的 ⋮**（`VoicePickerDialog:1562`） | 功能等价（标记三选 ❤️🚶😈 + 删除配置项，与 v10 的 ❤️🚶😈✖ 一一对应）；但需先进换声弹窗才够得着 |
| **试听** | 角色行右侧 **▶** → `previewVoiceByName` | 换声弹窗候选行的 **▶**（`VoicePickerDialog:1558`） | 同上 |
| **自定义关键词增删** | `showKeywordSelectionDialog` 内进入自定义关键词管理（v10 有 **4 个外部调用点**可达） | 只在**「释放并固定」流程**里可达（`RoleListScreen:586` → `KeywordPickerDialog:1016 / 979`） | 入口从**多路收窄到单路** |

第三项值得留意：Kotlin 换声弹窗走 DB 配置表、不靠关键词匹配，导致关键词弹窗的用途只剩「释放并固定」这一个流程，**自定义关键词的增删入口因此变窄**。数据仍是 `custom_keywords.json`（与插件互通），功能没丢，只是不好找。

## 9. 边界说明

本次审计只查「**入口 → 动作**」的可达性：

- **不含**动作内部的正确性 —— 那是《v10 复刻差异审计》的职责；
- **不含**实机表现 —— 全部结论来自代码阅读与静态扫描，一次真机未跑；
- **不含** UI 视觉 —— 窗口形态、间距、配色不在本次范围。

- 「释放并固定」流程**保留**（它用的是固定 12 关键词，不依赖自定义词）——但随后整条链路改了，见下

**追加（同日）：释放并固定改接换声弹窗，关键词弹窗整条退役**

目目 09-14：「释放并固定其实就是给角色解绑别名并更换发音人的意思，另立门户换发音人的意思，
其实可以接入更换发音人弹窗」。

- `KeywordPickerDialog` **整体删除**（含固定 12 关键词），文案 `role_keyword_title` 三处同删
- `VoicePickerDialog` 新增**释放模式**（`releaseOwnerName` / `releaseName`）：与「+ 添加角色」
  同一实现、同一落库入口族，只有落库分支不同（走 `releaseAndFix`）。释放时不显示角色名
  输入框（名字已定，标题「角色卡（名字）」即释放对象），候选 / 试听 / 确认键 / Toast 全复用
- **口径修正**：原实现把**裸关键词**（「女青年」）写进 `voice`，与本 App「voice=tag id」不一致，
  朗读时匹配不上发音人；现在由换声弹窗直接写 tag id（「女青年01」）
- **顺手修的坑**：释放弹窗原来存「记录快照」，释放主名后（aliases 首个顶上）在同一个弹窗里
  接着释放第二个时，拿旧 `ownerName` 去定位会找不到原角色 ⇒ 改存**下标**、每帧重取最新记录；
  释放行点过即标 ✓，防同名在同一弹窗里被释放两遍
- `addMode = createIfMissing || releaseOwnerName 非空`：原 `createIfMissing` 的各处判定统一收口，
  防调用方漏传新参数

⇒ 至此 v10 的「关键词选择」交互在本 App **不存在**：分类信息由发音人标签直接承担
（标签本身就是「中文分类词 + 序号」），少一跳、且与数据链口径一致。
