# 替换规则：导入与执行流程

本文档记录替换规则（ReplaceRule）的 JSON 格式、导入解析逻辑、执行时机与文本处理流程，以及一个已修复的 presetConfig 路径 bug。

## 一、数据结构

### ReplaceRuleGroup（替换规则组）

```kotlin
// lib-database/.../replace/ReplaceRuleGroup.kt
```

## 二、JSON 格式

```json
[
  {
    "group": {
      "id": 1687463653261,
      "name": "特殊符号发音",
      "order": 1,
      "onExecution": 1
    },
    "list": [
      {
        "id": 1687463823268,
        "groupId": 1687463653261,
        "name": "加号读作加",
        "isRegex": true,
        "pattern": "(?<=[\\d])\\+(?=[\\d])",
        "replacement": "加",
        "order": 1
      }
    ]
  }
]
```

- 顶层是数组 `List<GroupWithReplaceRule>`
- 每个元素含 `group`（分组）和 `list`（规则列表）
- `isEnabled` 可省略（默认 true）
- 多余字段会被忽略（`ignoreUnknownKeys=true`）

## 三、导入解析逻辑

**入口**：`ListImportBottomSheet.kt` → `doImportReplaceRule(json, type)`

```kotlin
private fun doImportReplaceRule(json: String, type: ImportType): AutoImportResult {
    val pairs = mutableListOf<Pair<ReplaceRuleGroup, ReplaceRule>>()
    if (json.contains("\"group\"")) {
        // 带分组结构
        AppConst.jsonBuilder.decodeFromString<List<GroupWithReplaceRule>>(json.toJsonListString())
            .forEach { gwt ->
                gwt.list.forEach { rule -> pairs.add(gwt.group to rule) }
            }
    } else {
        // 裸数组：生成新分组
        val group = ReplaceRuleGroup(name = StringUtils.formattedDate())
        AppConst.jsonBuilder.decodeFromString<List<ReplaceRule>>(json.toJsonListString())
            .forEach { pairs.add(group to it.apply { groupId = group.id }) }
    }
    pairs.forEach {
        dbm.replaceRuleDao.insert(it.second)     // 先插 rule
        dbm.replaceRuleDao.insertGroup(it.first)  // 再插 group
    }
    dbm.replaceRuleDao.updateAllOrder()
}
```

**关键点**：
- 用 `kotlinx.serialization` 反序列化（非 Gson）
- JSON 配置：`ignoreUnknownKeys=true` + `isLenient=true` + `explicitNulls=false`
- `json.contains("\"group\"")` 用字符串包含判断是否带分组（非 JSON 结构判断）
- 解析失败被 `runCatching` 吞掉，返回空列表，表现为"无可导入配置"

## 四、执行时机（onExecution）

```kotlin
// lib-database/.../constants/ReplaceExecution.kt
companion object ReplaceExecution {
    const val BEFORE = 0  // 朗读规则前
    const val AFTER = 1   // 朗读规则后
}
```

| 值 | 常量 | 含义 | 典型场景 |
|----|------|------|---------|
| 0 | BEFORE | 朗读规则处理**前**执行替换 | 过滤原文自带的 HTML 标签、段评等，避免朗读规则处理和发音人朗读这些内容 |
| 1 | AFTER | 朗读规则处理**后**执行替换 | 朗读规则产生的副产物（如段评标签）需要事后清除 |

**选择依据**：看要替换的内容是原文自带的（用 BEFORE）还是朗读规则产生的（用 AFTER）。

## 五、文本处理流程（TextProcessor）

```
TextProcessor.process(text, presetConfig)
  │
  ├── replacedText = replace(text, BEFORE)     // L115: BEFORE 阶段替换
  │
  ├── 路径1: presetConfig != null（指定配置朗读）
  │     └── splitAndAdd(replacedText, presetConfig)  // ✅ 已修复（原 bug: 用了原始 text）
  │
  ├── 路径2: isMultiVoice（多发音人）
  │     └── engine.handleText(replacedText, speechRules)  // ✅ 用替换后的文本
  │           └── 按 tag 分配发音人
  │
  └── 路径3: 单发音人
        └── splitAndAdd(replacedText, singleVoice)  // ✅ 用替换后的文本
  │
  └── 每个分片再经过 replace(fragment, AFTER)   // L120: AFTER 阶段替换
```

### TextReplacer.replace 逻辑

```kotlin
// app/.../help/TextReplacer.kt
fun replace(text: String, onExecution: Int): String {
    var s = text
    map[onExecution]?.forEach { rule ->  // 按 onExecution 取规则列表
        s = if (rule.isRegex)
            s.replace(Regex(rule.pattern), rule.replacement)
        else
            s.replace(rule.pattern, rule.replacement)
    }
    return s
}
```

- `map` 在 `load()` 时从数据库加载，按 `onExecution` 分组
- 只加载 `isEnabled=true` 的规则
- 正则用 Kotlin `Regex(pattern)`，支持 `(?i)`/`(?s)` inline flags、`\b`、`(?:...)` 等
- `replacement` 里的 `$1`/`$2` 引用捕获组

### 生效的必要条件

1. 替换功能总开关 `SystemTtsConfig.isReplaceEnabled` 开启
2. 规则 `isEnabled = true`
3. 规则所属组的 `onExecution` 与执行阶段匹配
4. `TextReplacer.load()` 已执行（初始化时或收到 `ACTION_UPDATE_REPLACER` 广播时）

## 六、已修复的 bug：presetConfig 路径丢弃 BEFORE 替换结果

**问题**：`TextProcessor.process()` 中，当使用预设/指定配置朗读（`presetConfig != null`）时，BEFORE 阶段的替换结果 `replacedText` 被计算出来却未使用，传给 `splitAndAdd` 的是原始 `text`。

**影响**：通过"指定配置"朗读时，BEFORE 阶段的替换规则不生效（如"过滤段评"功能失效）。

**修复**：`TextProcessor.kt` L134，`splitAndAdd(text, ...)` → `splitAndAdd(replacedText, ...)`

```kotlin
// 修复前
if (presetConfig != null) {
    splitAndAdd(text, presetConfig)           // ❌ 用原始 text
}

// 修复后
if (presetConfig != null) {
    splitAndAdd(replacedText, presetConfig)   // ✅ 用替换后的文本
}
```

多发音人路径（L136）和单发音人路径（L168）原本就正确使用了 `replacedText`，无需修改。
