# 日志栏架构

App 主界面第 2 个 Tab（index=1，`PagerDestination.SystemTtsLog`）是日志栏，展示系统 TTS 运行过程中的各类日志。本文档记录日志栏的汇聚机制、接入方式与过滤逻辑，供后续接入新日志源参考。

## 一、整体架构

```
日志栏 UI (TtsLogScreen, index=1 Tab)
   │
   ├── TtsLogViewModel.logs (内存列表 mutableStateListOf<LogEntry>)
   │     │
   │     ├── pull() ← cache/log/system_tts.log (启动恢复最近1500行)
   │     │
   │     ├── 源1: SysttsLogger.register { addLog(it) }
   │     │      ├── SystemTtsService.logS() 直接调用 (+写文件)
   │     │      └── SysttsFilter (Logback过滤器, 拦截 SystemTtsService.TAG + 指定 logger 名)
   │     │
   │     ├── 源2: Console.globalPluginLogListener = { addLog(it) }
   │     │      ← 各 Console(PLUGIN) 实例的 write() 触发
   │     │
   │     └── 源3: Console.globalSpeechRuleLogListener = { addLog(it) }
   │            ← Console(SPEECH_RULE) 实例的 write() 触发
   │
   ├── filteredLogs (级别 + 搜索词 + 插件开关 + 朗读规则开关)
   │
   └── LogScreen (LazyColumn 渲染, HTML消息着色, 自动滚动)
```

**核心设计**：三个全局监听器是汇聚点。所有日志源无论创建多少实例，都通过这三个汇聚点进入唯一的 `TtsLogViewModel.logs`，再经过滤后渲染到日志栏。

## 二、三个汇聚点

### 源1：SysttsLogger（原生 Kotlin 代码的日志）

- **定义**：`app/.../SysttsLogger.kt`，单例 object，内部用 `CopyOnWriteArraySet<LogListener>` 维护监听器
- **写入方式**：
  - 直接调用：`SysttsLogger.log(LogEntry(...))`，如 `SystemTtsService.logS()`（SUCCESS 级别，同时写文件持久化）
  - Logback 过滤器：`SysttsFilter`（继承 logback `Filter<ILoggingEvent>`），拦截指定 logger 名的事件，转成 `LogEntry` 投递给 SysttsLogger
- **白名单 logger**（`SysttsFilter`）：
  - `SystemTtsService.TAG`（系统 TTS 主日志）
  - `PLUGIN_LOGGER_NAMES`（插件相关，标记 `isPluginLog=true`）
  - `SYSTTS_INTERNAL_LOGGER_NAMES`（系统 TTS 内部模块，如 `SpeakerLoudnessManager`，`isPluginLog=false`）

### 源2 & 3：Console（脚本/JS 的日志）

- **定义**：`lib-script/.../console/Console.kt`，每个实例带 `source: LogSource`（PLUGIN 或 SPEECH_RULE）
- **机制**：`write(level, str)` 方法根据 source 调用对应的全局静态监听器：
  - PLUGIN → `Console.globalPluginLogListener`
  - SPEECH_RULE → `Console.globalSpeechRuleLogListener`
- **监听器赋值**：由 `TtsLogViewModel.init` 统一注册（`Console.globalXxxLogListener = { addLog(it) }`）
- **Console 实例创建点**：
  - 朗读规则引擎：`TextProcessor.kt` 创建 `Console(LogSource.SPEECH_RULE)`
  - 朗读规则编辑页：`SpeechRuleEditViewModel.kt`
  - 插件编辑页：`PluginEditorViewModel.kt`
  - 脚本运行时默认：`RhinoScriptRuntime.kt`（默认 PLUGIN）

## 三、接入新日志源

### 方式 A：原生 Kotlin 代码（走 SysttsLogger + SysttsFilter）

适用于 lib-tts / app 模块的 Kotlin 代码。

1. 在产生日志处用 `KotlinLogging.logger("LoggerName")` 创建 logger，调用 `logger.info { "..." }` 等
2. 在 `SysttsFilter.kt` 的 `SYSTTS_INTERNAL_LOGGER_NAMES`（非插件）或 `PLUGIN_LOGGER_NAMES`（插件）加入 logger 名
3. 日志经 logback → SysttsFilter 拦截 → SysttsLogger → 日志栏，自动显示

> 注意：lib-tts 不能直接引用 app 模块的 SysttsLogger，但走 Logback 过滤器无需直接引用——只要 logger 名在白名单里，SysttsFilter 会自动拦截转发。

### 方式 B：新增独立日志类别（带独立开关）

如果需要独立的显示开关（不混在插件/朗读规则日志里）：

1. `LogEntry.kt`（lib-common）新增 `isXxxLog: Boolean = false` 字段
2. `Console.kt` 新增 `LogSource` 枚举值 + 全局监听器字段 + write() 分支（若走 Console 机制）
3. `TtsLogViewModel.kt` init 块注册新监听器；新增 `showXxxLogs` 状态字段；`filteredLogs` 加过滤分支
4. `LogFilterDialog.kt` 新增 FilterChip 开关
5. `TtsLogScreen.kt` 把新开关传给 LogFilterDialog

## 四、过滤逻辑（TtsLogViewModel.filteredLogs）

四维度过滤：

1. **日志级别** `selectedLevels`（默认空=全部显示）
2. **搜索词** `searchQuery`（匹配 message 或 time）
3. **插件日志开关** `showPluginLogs`（默认隐藏）
4. **朗读规则日志开关** `showSpeechRuleLogs`（默认隐藏）

> 归入系统日志（`isPluginLog=false`、`isSpeechRuleLog=false`）的条目**默认显示**，不受任何开关控制。

## 五、持久化

- 只有 `SystemTtsService.logS()`（SUCCESS 级别）会写文件 `cache/log/system_tts.log`
- 插件日志、朗读规则日志只在内存中，不持久化
- `TtsLogViewModel.pull()` 启动时从文件读取最近 1500 行恢复
- `clear()` 清空内存列表并清空文件

## 六、关键文件速查

| 文件 | 作用 |
|------|------|
| `app/.../compose/systts/TtsLogScreen.kt` | 日志栏 UI（TopAppBar + 筛选 + 列表） |
| `app/.../compose/systts/TtsLogViewModel.kt` | 日志收集、过滤、持久化 |
| `app/.../compose/systts/LogScreen.kt` | LazyColumn 渲染日志条目 |
| `app/.../compose/systts/LogFilterDialog.kt` | 筛选对话框（级别 + 开关） |
| `app/.../SysttsLogger.kt` | 系统 TTS 日志单例 |
| `app/.../SysttsFilter.kt` | Logback 过滤器（logger 名白名单） |
| `lib-script/.../console/Console.kt` | 脚本日志（PLUGIN / SPEECH_RULE） |
| `lib-common/.../LogEntry.kt` | 日志数据模型 |
| `lib-common/.../LogLevel.kt` | 级别定义、颜色映射 |

## 七、旁路日志组件（非日志栏主路径）

- `LoggerBottomSheet.kt`：代码编辑器底部日志面板，用实例级监听器（非全局），只显示单个 Console 实例的日志
- `LoggerFloatingScreen.kt` / `LoggerFloatingManager.kt`：悬浮窗日志，独立系统
