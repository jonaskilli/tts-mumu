# 插件提交判定指导（给 TTS-Server 维护者 / AI 协作）

> 用途：当要把一个新插件（或插件改动）交给我（AI）处理时，我如何判断该插件是否需要特殊配置、是否需要勾选「由插件处理」开关。

---

## 一、先判断：这个插件是否会"自己处理"音频参数

> ⚠️ 现状说明（2026-08-19）：App **目前还不能自动判断**插件是否消费 rate/音量/音调。v1.28 仅把「由插件处理」开关内联到滑块下方并加说明文字，**仍需人工/维护者判断后手动勾选**。以下判定方法供人工使用，后续可做成自动检索插件 JS 的辅助工具。

插件音频参数有三项是 App 本机会再叠加处理的：**语速、音量、音调**。

判定方法——看插件 JS 源码里是否消费了这三个参数：

| 参数 | App 侧处理 | 插件"已处理"的信号 |
|---|---|---|
| 语速 (speed/rate) | 本机 Sonic 变速 | 插件把 rate/speed 发给服务端做变速（如纳米 AI、`audioParams.speed`、`reqSpeed`） |
| 音量 (volume) | 本机 Sonic 调音量 | 插件自行设置音量 / 增益 / `audioParams.volume` |
| 音调 (pitch) | 本机 Sonic 变调 | 插件发送 pitch / `audioParams.pitch` 给服务端 |

**判定规则**：
- 插件**消费了**某参数 → 必须勾选对应的「已由插件处理」，否则该参数被乘两次（语速尤为明显，听感翻倍）。
- 插件**不消费**某参数 → 不勾选，由本机 Sonic 正常兜底。

---

## 二、提交插件时请附上的信息

把插件发给我时，请尽量包含：

1. **插件 JS 源码**（或核心合成函数片段）。
2. **该插件发送请求时携带的参数**（尤其 `speed` / `volume` / `pitch` 字段名）。
3. **是否调用了音频变速/变调接口**（如服务端 rate、音频处理 API）。
4. **试听表现**（语速是否明显偏快、音调是否异常）。

我会据此：
- 搜索插件源码中是否出现 `speed`/`rate`/`volume`/`pitch` 等字段；
- 确认这些字段是否被发往服务端或用于本地音频处理；
- 给出「语速/音量/音调 是否需勾选由插件处理」的结论，并说明依据。

---

## 三、我已确认的已知插件清单（示例）

| 插件 | 语速 | 音量 | 音调 | 说明 |
|---|---|---|---|---|
| 纳米 AI 类 | ✅ 已处理 | 视实现 | 视实现 | 典型会自己发 rate，必勾「语速已由插件处理」 |
| 普通不消费参数插件 | ❌ | ❌ | ❌ | 全不勾，Sonic 兜底 |

> 新插件确认后请补充到此表，减少重复判断。

---

## 四、判断流程（速查）

```
收到插件
  → 搜源码是否出现 speed/rate/volume/pitch
    → 否 → 三项都不勾
    → 是 → 看该字段是否被发往服务端 / 用于音频处理
              → 是 → 勾对应「已由插件处理」
              → 否（仅读取未使用）→ 不勾
  → 不确定 → 实测：勾选前后分别试听语速，偏快则必须勾
```

---

## 五、相关代码位置（便于核对）

- 开关字段：`plugin_handles_speed` / `plugin_handles_volume` / `plugin_handles_pitch`（数据库 v32）
- UI 开关：`app/.../compose/systts/plugin/PluginAudioParamsDialog.kt`（内联在滑块下方）
- 处理逻辑：本机 Sonic 叠加处会读取上述开关决定是否跳过
