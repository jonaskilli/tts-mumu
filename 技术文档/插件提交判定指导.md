# 插件提交判定指导（给 TTS-Server 维护者 / AI 协作）

> ⚠️ **本文档的"人工判定勾选"方法已废止（2026-09-10 用户裁定）**
>
> 裁定内容：软件**分辨不出**插件是否属于"自己处理参数"的特殊型，既不该让使用者判断，也不该让维护者逐个识别、手动记录。
> 一律按**本机处理**执行，验收标准只有三条：**能播放、能调速、能调音量**。
>
> 现行实现（commit `dc5dd22` 起）：
> - 语速 / 音量 / 音高 **恒显示、恒可调**，不再有隐藏或不可调的维度
> - 全部维度 **恒走本机 Sonic**；宿主把中性值（1f，引擎层 ×50 转成插件的 50 制刻度）发给插件，插件收到的就是"别动"
> - 因此**不存在双重叠加**，也**不存在"调了不生效"**
> - 终值 = 插件层 × 配置层 × 全局层（`resolveTtsPlayback` 的 `multiplyParam`，FOLLOW 视为 1），本机 Sonic 吃的就是这个终值；三层同属一条链路，性质相同
> - DB 的 `plugin_handles_speed/volume/pitch` 三列与 `parameterRoute()` 的 legacy 入参保留，但无 UI，恒为 false
>
> **勿再提议**：由插件处理开关、自动探测路由表、重建人工已知表。以下正文仅作历史背景保留。

> 用途（历史）：当要把一个新插件（或插件改动）交给我（AI）处理时，我如何判断该插件是否需要特殊配置、是否需要勾选「由插件处理」开关。

---

## 一、先判断：这个插件是否会"自己处理"音频参数

> ⚠️ 现状说明（2026-08-19）：App **目前还不能自动判断**插件是否消费 rate/音量/音调。v1.28 仅把「由插件处理」开关内联到滑块下方并加说明文字，**仍需人工/维护者判断后手动勾选**。以下判定方法供人工使用，后续可做成自动检索插件 JS 的辅助工具。

插件音频参数有三项是 App 本机会再叠加处理的：**语速、音量、音调**。

判定方法——看插件 JS 源码里是否消费了这三个参数：

| 参数 | App 侧处理 | 插件"已处理"的信号 |
|---|---|---|
| 语速 (speed/rate) | 本机 Sonic 变速 | 插件把 rate/speed 发给服务端做变速（如纳米 AI、`audioParams.speed`、`reqSpeed`） |
| 音量 (volume) | 本机 Sonic 调音量 | 插件自行设置音量 / 增益 / `audioParams.volume` |
| 音调 (pitch) | 本机 Sonic 变调 | 插件发送 pitch / `audioParams.pitch` 给服务端 |

**判定规则**：
- 插件**消费了**某参数 → 必须勾选对应的「已由插件处理」，否则该参数被乘两次（语速尤为明显，听感翻倍）。
- 插件**不消费**某参数 → 不勾选，由本机 Sonic 正常兜底。

## 二、提交插件时请附上的信息

把插件发给我时，请尽量包含：

1. **插件 JS 源码**（或核心合成函数片段）。
2. **该插件发送请求时携带的参数**（尤其 `speed` / `volume` / `pitch` 字段名）。
3. **是否调用了音频变速/变调接口**（如服务端 rate、音频处理 API）。
4. **试听表现**（语速是否明显偏快、音调是否异常）。

我会据此：
- 搜索插件源码中是否出现 `speed`/`rate`/`volume`/`pitch` 等字段；
- 确认这些字段是否被发往服务端或用于本地音频处理；
- 给出「语速/音量/音调 是否需勾选由插件处理」的结论，并说明依据。

## 四、判断流程（速查）

```
收到插件
  → 搜源码是否出现 speed/rate/volume/pitch
    → 否 → 三项都不勾
    → 是 → 看该字段是否被发往服务端 / 用于音频处理
              → 是 → 勾对应「已由插件处理」
              → 否（仅读取未使用）→ 不勾
  → 不确定 → 实测：勾选前后分别试听语速，偏快则必须勾
```

### 6.6 宿主侧机制（结论依据）

- `PluginTtsProvider.getStream()`：插件负责的维度发真实值，本机负责的维度发 `1f`
- `TtsPluginEngineV2.getAudio()`：`r = (rate*50).toInt()`，把倍率转成插件用的 50 制刻度（1f → 50 = 正常）
- `ResolvedTtsPlayback.resolveTtsPlayback()`：`finalParams = 插件层 × 配置层 × 全局层`（FOLLOW 视为 1）
- `DefaultResultProcessor`：插件负责的维度清为 1f，其余按终值走本机 Sonic
- ⇒ 结论：**三项调节恒生效，不会翻倍，也不会被吞掉**；代价是放弃服务端原生处理（音高差异最大、语速次之、音量几乎无差），按 09-10 裁定接受此折损。
