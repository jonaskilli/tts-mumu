## 一、目录总览（对照实机文件逐一说明）

所有文件都在 **`/storage/emulated/0/Download/chajian/mingwuyan/`** 下（`mingwuyan` = 朗读规则的 ruleId，换规则就是换文件夹）。

### 角色 / 标签类（本文档主线）

| 文件 | 是什么 | 谁写 | 谁读 | 生命周期 |
|---|---|---|---|---|
| **characterRecords.json** | 角色绑定表**本体**（角色名→发音人标签） | 朗读规则、角色管理、快捷栏换绑 | 三方都读 | 长期保存 |
| **gengxin.json** | "角色表更新了"的**信件**（全量快照） | 角色管理保存时、快捷栏换绑后 | 朗读规则（每轮朗读开头） | **临时**：被消费后立即删除 |
| **fayinren.json** | 发音人标签池（候选列表） | 朗读规则（每轮朗读后） | 角色管理、快捷栏 | 规则运行时持续刷新 |
| characterRecords_backup.json | 角色表备份 | 角色管理保存时 | 防框架从旧备份恢复 | 长期保存 |
| shuming.<书名>.json | 按**书**分开存的角色表（书名默认"默认"） | 角色管理保存时 | 角色管理（换书时恢复） | 长期保存 |
| liebiao.json | **书名列表**（存过哪些书；空/损坏时初始化为 `["默认"]`） | 角色管理 | 角色管理（切书菜单） | 长期保存 |
| cunfang.txt | **当前书名**记录（"存放"——支持框架自动切换书籍） | 朗读规则（切书时写"默认"等） | 角色/规则（确定用哪个 shuming 文件） | 长期保存 |
| voice_marks.json | 发音人**标记**：`{ "标签id": ["like","neutral","bad"], ... }`（❤️🚶😈，数组多选；JS 旧格式 string 值读取时兼容转数组） | 角色管理、快捷栏标记 | 角色管理、快捷栏（双向互通） | 长期保存 |

### 密钥 / 接口类（角色 AI 分析的"钥匙串"）

| 文件 | 是什么 | 说明 |
|---|---|---|
| key_list.json | **API 密钥列表主文件**（消费端唯一数据源） | 值格式=`网址@@模型名@@Key`；同一模型可挂多个接口 |
| key_list.backup.json | key_list 的备份 | 主文件损坏时自动恢复（运行时自动同步的副本） |
| api_center.json | **接口中心**数据层 | 无它时把 `@@` 密钥按（网址+密钥）聚合成接口组（默认名"接口N"），纯 key 留直连组 |
| miyue.txt | API 密钥（当前生效） | 朗读规则读它同步 apiKey 进内存（角色分析用） |
| miyue_backup.txt | miyue.txt 的备份 | 运行时自动同步的副本 |
| gengxin.txt | 密钥同步中转 | 规则从它同步 apiKey（与 gengxin.json 信箱是两回事） |
| 密钥导出_YYMMDD.json | 密钥**导出**产物 | 角色管理"导出密钥"功能手动生成，导入功能按它合并（重名跳过） |

### 界面 / 其他

| 文件 | 是什么 | 说明 |
|---|---|---|
| theme.json | 角色管理的**主题选择**持久化 | 仅角色管理自己读写 |
| custom_keywords.json | 自定义关键词（可选，初始化核心文件集合时列出） | 未使用时不出现 |

> 角色管理自己把 gengxin.json / miyue_backup.txt / characterRecords_backup.json 归类为"运行时自动同步的副本，不需备份"——换机迁移时可以不管这三个。

## 二、characterRecords.json —— 角色绑定表（核心）

**它管的事**：哪个角色（或角色关键词）用哪个"发音人标签"读。

**长这样**（字段名是历史约定，照原样列）：

```json
[
  {
    "name": "张三",
    "aliases": "张三|老张",
    "voice": "女青年01",
    "gender": "女",
    "age": "女青年",
    "usageCount": 100,
    "genderAgeHistory": [{ "gender": "女", "age": "女青年" }]
  }
]
```

| 字段 | 含义 | 备注 |
|---|---|---|
| `name` | 角色名（主名） | 分配角色时的查找键 |
| `aliases` | 别名，`|` 分隔 | "老张"也归到张三（别名投票合并用） |
| `voice` | **该角色绑定的发音人标签（tag）** | ⚠️ 名字叫 voice，但存的**不是** TTS 引擎 voice，是"女青年01"这种标签——历史命名，读代码时最容易懵的就是它 |
| `gender` / `age` | 角色性别/年龄 | 新角色自动分配时一并记录 |
| `usageCount` | 使用计数 | 100/50 时触发规则内的维护逻辑（置顶/校验） |
| `genderAgeHistory` | 性别年龄变化历史 | 角色性别判断变化时追加 |

**一个"标签（tag）"可以挂多个配置项（多个 voice）**：运行时规则说"这段用女青年01读"，app 在所有 tag=女青年01 的启用配置里随机选一条——所以换绑改变的是"用哪个标签"，同标签内换具体声音则是改各配置项自己的归属。

## 三、gengxin.json —— 更新信件（机制核心，最容易被忽略）

**为什么需要它**：朗读规则把角色绑定表记在**内存**里（黑板），characterRecords.json 只是存档复印件。规则运行中**不会反复读存档**——只改存档不改黑板，规则根本不知道。

**它的工作方式（信箱机制）**：

1. 谁改了绑定，就把**改完后的完整角色表**写进 gengxin.json（相当于"投信"）
2. 朗读规则**每轮朗读开头**查信箱：有信 → 照着信把内存角色表整个替换 → **删除 gengxin.json**（消费掉，防重复生效）
3. 没信 → 内存不动

**谁在投信**：
- 角色管理：每次保存角色表都会写它（还有 createGengxinFile 单独补写）
- **快捷栏换绑（09-12 新增）**：以前只写 characterRecords.json 不投信 → 规则内存是旧的，换绑不生效，甚至规则下次保存时用旧内存把修改覆盖掉。现在换绑后同步投信，与角色管理完全互通。

**注意**：它是临时文件，**正常情况下你看不到它**——朗读一轮就被规则删掉了。如果你在文件管理器里长期看到 gengxin.json 躺着没被删，说明规则还没跑到下一轮朗读。

## 四、fayinren.json —— 发音人标签池（候选列表的来源）

**长这样**（纯字符串数组）：

```json
[
  "男/少年",
  "女青年01",
  "女青年02",
  "男主",
  "旁白",
  "【】括号发音人"
]
```

- **由朗读规则生成**：每轮朗读后把"当前可用的发音人标签"写进来（duihua 动态标签置顶、硬编码标签后置；`CONFIG.saveVoicesToFile == 1` 时才写）
- **是"更换发音人"的候选来源**：角色管理和快捷栏弹出的候选列表，就是拿这个池子过滤出来的
- 池子里放的是**标签（tag）原值**——"女青年01"这种中文名就是 tag 本身（规则注释原话："key 直接用 tag（如'女青年01'）"），不是 TTS 引擎的 voice

## 五、密钥与书名类的补充说明

- **密钥链路**：`key_list.json`（主数据）→ 接口中心 `api_center.json` 分组 → 生效密钥写 `miyue.txt`（+ `miyue_backup.txt`/`gengxin.txt` 同步）→ 朗读规则读它做 AI 角色分析。`key_list.backup.json` 与 `miyue_backup.txt` 都是自动副本。
- **书名链路**：`cunfang.txt`（当前书名，如"默认"）→ 决定读哪个 `shuming.<书名>.json`；`liebiao.json` 是书名清单（切书菜单的来源）。
- **密钥导出_YYMMDD.json**：手动"导出密钥"生成、手动"导入密钥"消费，运行流程不碰它。
- **命名拼音对照**：miyue=密钥、gengxin=更新、fayinren=发音人、liebiao=列表、cunfang=存放、shuming=书名。

## 六、角色分配链（规则每读一条对话时的完整决策）

```
台词进来
 ① 台词里带 <<发音人标签>> ？
    └ 有 → 直接用标注的标签（手工指定，跳过 AI 分析）
 ② AI 角色分析 → 角色名 + 性别 + 年龄
 ③ 查 characterRecords 绑定表（角色名/别名匹配）
    └ 已有记录 → 复用 record.voice（该角色绑定的标签）
       （绑定的标签失效=配置被删 → 重新自动分配并写回）
    └ 新角色 → 从同"性别/年龄"池里挑一个未被占用的标签，
       写入 characterRecords（一次分配终身绑定）
 ④ 都不行 → 按性别兜底：男→duihuaA、女→duihuaB、识别不出→duihuaA（09-12 改：不再回落 duihua，duihua 弃用）
 ⑤ 返回标签 → app 按配置项的 tag 匹配（同标签下多配置随机选一条读）
```

对应到配置项字段：规则的标签 = 配置项的 `speechRule.tag`（内部键），列表角标显示的是 `tagName`（显示名）。**app 匹配配置、面板换绑、角色管理互查，全部用 tag**；tagName 只负责给人看。

## 七、三方互通关系（现状）

| 操作 | 角色管理 | 朗读规则 | 快捷栏（app） |
|---|---|---|---|
| 换发音人 | 写角色表四件套（含 gengxin.json 信） | — | 写角色表 + gengxin.json 信（09-12 补齐） |
| 分配新角色 | — | 同性别/年龄池自动派 + 写角色表 | — |
| 候选列表 | 读 fayinren.json | 生成 fayinren.json | 读 fayinren.json ∩ 启用配置 |
| **标记发音人**（09-12） | 读写 voice_marks.json | — | 读写 voice_marks.json（`VoiceMarksFile.kt`，双向实时互通；v10 已去缓存早退防覆盖） |
| **删除配置项**（09-12） | 删第一条匹配配置 + 从池子移除标签 | 规则自动重分配受影响角色 | 只删 ▶ 试听的那一条；**删空标签才从池子移除** |
| 生效时机 | 规则下一轮朗读开头（消费 gengxin.json） | 即时（它就是执行者） | 规则下一轮朗读开头 |

三方读写同一套文件、同一个字段（tag），任意一方改动都会通过 gengxin.json 信件同步给规则，再由规则反映到实际朗读。

## 八、全景：chajian 只是"冰山一角"（软件全部本地数据地图）

mingwuyan 文件夹只是**插件协作层**。TTS 软件的全部本地数据分三层：

### 1. 应用私有目录（`/data/data/...`，无 root 看不到）——真正的家底
- **systts.db**（Room 数据库）：配置项、分组、**替换规则**、**插件实体**、**朗读规则（含 JS 本体）**、旧版配置——全在这一个库里。
  > 所以"朗读规则 JS 本体"不是文件，存在数据库里；chajian 文件夹里只有规则**运行时**产生的协作数据。
- **SharedPreferences / DataStore**：软件的各项设置开关（AppConfig）。
- → 换机/迁移走**软件内的备份功能**（可导出到网盘/本地），文件管理器里看不到这层。

### 2. 公共存储 `Download/chajian/`（本文档主线）
插件们的**协作文件夹**：每个插件/规则一个子目录（规则用 ruleId、插件用 pluginId），互相通过"写文件"交换数据（角色绑定、发音人池、密钥……）。mingwuyan 是其中一个。

### 3. 其他公共存储文件（app/插件主动读写）
- **`/sdcard/data/`**：克隆音频目录（放 MP3/WAV），软件扫描后在其下生成 `音频列表.json`（克隆列表功能）。
- **插件导出文件**：配置/分组/规则/插件的导出 JSON，存在你导出时选的位置。
- **`/sdcard/Download/deepseek_sse.txt`**：DeepSeek 代理的调试日志（仅调试模式产生）。
- 各插件还可以有自己的子目录与文件（约定同 mingwuyan 模式：插件 JS 用 ttsrv 读写自己文件夹）。

> 一句话：**看得见的 chajian 文件夹是"插件协作 + 缓存"，看不见的数据库才是"全部配置本体"。** 备份迁移：软件数据用软件内备份，chajian 文件夹整个拷走即可（其中 gengxin.json 是临时信件，可不管）。
