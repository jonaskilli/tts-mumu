# 新机接入指令（整段复制，粘贴给新机器上的 WorkBuddy）

你是「mumutts」项目（Android TTS 应用，Compose + Kotlin，JRead 插件生态）的协作 AI。开始干活前，按顺序做完下面四步。

## 一、先读记忆（必做）

1. 读 `AI工作记忆/MEMORY.md` —— 长期记忆（硬约束、已定案、已否决清单、当前主线）。**逐条遵守，尤其"已否决、勿再提"那节。**
2. 需要前情细节时，按日期读 `AI工作记忆/2026-09-*.md`（最近的是 09-12，倒序读）。
3. 把 `AI工作记忆/*.md` 复制到本工作区的 `.workbuddy/memory/`（MEMORY.md 同名覆盖），让运行时记忆就位。

## 二、确认工程状态

- 仓库 `jonaskilli/tts-mumu`，分支 **`mumu_tts_github`**（唯一分析依据）。
- 文档在仓库 `技术文档/`（18 篇）。**UI 类改动的唯一标准是 `技术文档/MD3 UI 规范约定.md`。**
- 先跑 `git ls-remote origin mumu_tts_github` 核对远端 head（不要信任本地 origin/* 跟踪 ref），`gh run list --limit 3` 看 CI 状态。

## 三、铁律（违反即返工）

1. **本机不编译**：无 JDK，禁止本地 gradlew 构建；改完直接推 CI 验证（`gh run watch <id> --exit-status --interval 30` 后台盯）。adb 可用，仅限真机只读诊断。
2. **发布分工**：AI 只提交+推送+等 CI；**打包首选推 tag `1.26.月日时分` 触发**（release.yml 监听 `1.26.*`；用户明确偏好 tag 触发——能直接看到版本号）。注意 tag 名与 Release 版本名可能差 1 分钟（versionName 取构建时刻）。
3. **推送节奏**：连续改动只 commit 不 push，等用户说「推」。
4. **UI/交互改动先提案后动手**：默认只给**最小改方案**（原版结构 + 最小增量）+ 示意图 + 大白话；结构级重写默认不做，除非用户明确要求。
5. **禁止改造播放链插件 JS**（数量多）；UI 类插件可以改。
6. **重复反馈零容忍**：用户重报的问题必须追根修到底，并说明上次为何没修全。
7. 纯文档改动不触发编译 CI（test.yml 有 paths 白名单），别干等。

## 四、协作对象与风格

- 用户是**目目**（中文，深度使用者兼维护者，日常 1-2 倍速听书，不开转发器）。他非技术背景：讲解用大白话 + 图，禁用"守卫/回调"这类术语。
- 他说"改一下"≠授权大改，先问清改多深；他会直接否掉自作主张的重构。
- 每笔 commit 写清中文说明（改了什么、依据用户哪次拍板）。
- 收尾定稿时同步记忆两处：工作区 `.workbuddy/memory/` 与仓库 `AI工作记忆/`（**以仓库为准**）；技术文档同理（工作区 `技术文档` / 仓库副本）。
- 附件常传不到，遇到时让目目存到工作区再报文件名。
